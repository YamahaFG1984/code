为什么要「系统化」地测试？

如今没有人再争论测试是否重要，开发者也都会用 JUnit、pytest 这样的工具。但会用工具，不等于会设计测试。 大多数人测试时凭直觉：想到什么测什么。结果是 —— 两个开发者对同一段代码写出完全不同的测试，而 Bug 恰好藏在两个人都没想到的地方。

这本书的核心主张是：测试可以既高效（用最少的力气找到最多的 Bug，每种技术都有明确的起点和终点）又系统（换一个人来做，也能推导出差不多的测试集）。 把能系统化的部分系统化，把人的创造力留给真正需要它的地方。

这套教程写给谁

  • 会写代码、但测试全凭感觉的开发者。每章从「为什么需要这个技术」讲起，再一步步演示怎么用。
  • 用 Python 或 TypeScript、不写 Java 的人。原书全是 Java，这里每个示例都有另外两种语言的地道写法，工具也换成了对应生态里的主流选择。
  • 已经在写测试、想更进一步的人：MC/DC、变异测试、属性测试、有状态测试、页面对象、测试异味……这些主题平时很少被系统地讲清楚。

怎么用这套教程

📑

切换语言

每个代码块上方都有 Java / Python / TypeScript 标签。点任意一个，整页所有代码块都会切换，并记住你的选择。

🗺

先看图

每一章都有大量图示。卡住的时候，先看图把概念弄清楚，再回来读代码。

✍

亲手敲

每章末尾有「自测练习」（附书中答案，点开查看）和「动手练习」。看懂和写出来之间的差距，比你想象的大。

🖥

跑仓库代码

仓库里每章一个独立的 Maven 项目（ch1 … ch10、intro-to-junit），进入目录运行 mvn test 即可。

💡 关于 Python 和 TypeScript 示例

Python 示例使用 pytest、Hypothesis、unittest.mock、pytest-playwright；TypeScript 示例使用 Vitest、fast-check、@playwright/test，数据库示例使用 SQLite（Python 的 sqlite3、Node 22+ 的 node:sqlite）。 这些示例在编写本教程时都实际运行过：在 Python 3.12 + Hypothesis 6 和 Node 24 + Vitest + fast-check 4 下通过，Web 测试针对仓库中的 PetClinic jar 实际跑过。 个别地方，不同语言的行为会不同（比如字符串的对象身份、NaN 的生成、日期的月份从 0 开始），页面里都专门做了说明。

🔑 一句话总结

如果你只记住一件事：测试的难点不在于写 JUnit 代码，而在于设计出能发现 Bug 的用例。 这套教程剩下的 11 章，都是在教你如何系统地做到这一点。
